# راه‌اندازی پنل مدیریت فروشگاه امید

## پروژه پایگاه داده
- نام پروژه: `omid-store`
- شناسه پروژه: `jubvmlmshubesubfmvsc`
- منطقه: `eu-central-1`
- نشانی API: `https://jubvmlmshubesubfmvsc.supabase.co`

## وضعیت فعلی
ساختار پایگاه داده روی پروژه Supabase اعمال شده است. جدول‌ها شامل `profiles`، `categories`، `products`، `orders` و `order_items` هستند. سیاست‌های RLS فعال‌اند. تابع `place_cash_order` قیمت و موجودی را در سرور بررسی می‌کند و سفارش پرداخت در محل را به‌صورت اتمیک ثبت می‌کند.

## ساخت حساب مدیر
1. در Supabase وارد بخش Authentication → Users شوید.
2. حساب مدیر را با ایمیل خودتان ایجاد کنید (ثبت‌نام مشتری از داخل اپ نیز بعداً اضافه می‌شود).
3. پس از ایجاد حساب، از SQL Editor استفاده کنید و فقط ایمیل حساب خودتان را در دستور زیر جایگزین کنید:

```sql
update auth.users
set raw_app_meta_data =
  coalesce(raw_app_meta_data, '{}'::jsonb) ||
  jsonb_build_object('role', 'admin')
where email = 'YOUR_ADMIN_EMAIL@example.com';
```

4. از حساب خارج شوید و دوباره وارد شوید تا توکن جدید با نقش مدیر دریافت شود.

**مهم:** نقش مدیر را از `user_metadata` قابل‌ویرایش توسط کاربر تنظیم نکنید. فقط `app_metadata` سمت سرور معتبر است. هرگز کلید `service_role` یا کلید مخفی را در APK یا GitHub قرار ندهید.

## افزودن کالا
پس از ساخت حساب مدیر، کالاها و دسته‌بندی‌ها را از Table Editor اضافه کنید. هیچ کالای ساختگی در پایگاه داده درج نشده است؛ فروشگاه تا زمان افزودن کالاهای واقعی خالی می‌ماند.

## سفارش واقعی
تابع RPC زیر سفارش را ایجاد می‌کند:
`place_cash_order(p_customer_name, p_phone, p_delivery_address, p_items, p_notes)`

`p_items` باید آرایه‌ای از اشیای دارای `product_id` و `quantity` باشد. قیمت ارسالی از اپ پذیرفته نمی‌شود؛ سرور قیمت فعلی را از جدول محصولات می‌خواند و موجودی را کاهش می‌دهد.

## امنیت
- RLS روی همه جدول‌های عمومی فعال است.
- مشتری فقط سفارش‌های خودش را می‌بیند.
- فقط مدیر می‌تواند محصولات و دسته‌بندی‌ها را مدیریت کند و وضعیت سفارش‌ها را تغییر دهد.
- کلید publishable/anon برای برنامه موبایل قابل استفاده است؛ کلید service_role هرگز نباید در برنامه قرار بگیرد.
